# AI 功能约定卡（docs/ai-agreement.md）

## 中文效果约定（学生确认部分）
1. 必须先登录，并打开一条已保存、自己有权查看的报修单。
2. 点击按钮后，网站根据这条报修的设备和故障描述，生成三条相关、通俗、适合普通人安全检查的建议。
3. 生成中显示“正在生成”，按钮暂时不能重复点击。
4. 建议跟随这条报修保存；刷新页面，或同组另一位同学打开同一单，仍能看到。
5. 生成失败时提示暂时无法获取、可稍后重试；原报修和已有建议不能消失。若建议已生成但保存失败，要提示没有保存成功。
6. 建议只作参考，不指导带电拆机等危险操作；需要专业维修时明确提示。

## 效果示例（打印机故障）
- 报修：设备“打印机”，故障“发送打印任务后没有反应”。
- 期望建议示例：
  1. 检查打印机电源线和数据线是否插紧，电源指示灯是否正常。
  2. 取消卡住的打印任务后重启打印机，再重新发送一次打印任务。
  3. 换一个 USB 端口或检查纸张是否卡滞；若仍无反应，请联系专业维修人员上门处理。

## 供开发助理读取的技术细节
- 前端（A）：详情页“获取排查建议”按钮；生成中按钮禁用并显示等待提示；三条建议列表渲染；失败展示可重试提示。
- 后端（B）：`POST /api/suggestions/:id`；校验登录与报修归属；调用 AI 服务；结果写入 `repair_suggestions`；已存在建议时直接返回，避免重复消耗额度。
- 密钥仅放在服务端环境变量，不下发浏览器、不进入仓库；不带 `NEXT_PUBLIC_` 前缀。
- 异常覆盖：空内容、无权访问、AI 服务失败、返回条数异常、建议保存失败。
