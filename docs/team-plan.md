# 分工卡（docs/team-plan.md）

## 项目目标
办公团队内部报修网站：填写测试姓名、办公区、设备和故障描述；查看列表、详情；修改待处理 / 处理中 / 已完成状态；两名测试账号可看到同组报修；点击按钮生成三条 AI 排查建议并持久保存。

## 分工

| 角色 | 负责模块 |
|---|---|
| A（页面与上线） | 表单、列表、详情、状态按钮、AI 建议显示、Vercel 部署 |
| B（数据与 AI） | 登录与共享数据、报修保存与查询、同组权限、AI 服务与建议保存 |

## 不可同时修改的公共文件
- `index.html`：页面结构与公共样式，改动前先在组内说明。
- `api/_lib/`：公共工具（会话、Supabase 客户端、AI 调用），涉及对方模块时先沟通。
- `supabase/schema.sql`：表结构变更需双方确认。

## 各阶段完成标准
1. 框架：最小页面可打开，示例数据明确标注为演示。
2. 页面：表单必填校验、列表展示、详情与状态操作可试用。
3. 数据：保存后刷新可见，同组两人可互相查看修改；未登录不可读写。
4. AI：详情页按钮 → 等待提示 → 三条相关建议；刷新或另一账号打开同一单仍可见；失败有提示且原数据不丢失。
5. 变更：按状态筛选列表，可恢复“全部”。

## 交接规则
- 个人分支从最新 `work` 拉出；个人 PR 目标分支为 `work`；最终发布 PR 目标为 `main`。
- PR 正文写明：做了什么、如何试用、已通过的检查、未完成项、需要队友配合的点。
- 检查者按 PR 步骤实际操作网页；问题写清预期与实际，作者在原分支修复并更新同一 PR。
- 合并前再次核对目标分支与最新检查结果。
